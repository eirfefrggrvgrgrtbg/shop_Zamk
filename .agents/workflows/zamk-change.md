# ZAMK Change Workflow

Workflow для безопасного внесения изменений в рамках строго поставленной задачи с валидацией через существующие Skills.

## 1. Preflight
- Запустить skill `zamk-preflight`.
- Зафиксировать baseline репозитория.
- Классифицировать незавершённые изменения (например, SA.5 dirty work) и stashes как чужие/неприкасаемые. Никогда не сбрасывать и не затирать их.

## 2. Implement Declared Scope
- Реализовать строго согласованный скоуп задачи, следуя правилам `.agents/rules/zamk-core.md`.
- Не модифицировать файлы вне скоупа задачи.
- Соблюдать FBO модель и границу ответственности (Seller не выполняет физические операции склада ZAMK).

## 3. Relevant Checks
- Выполнить релевантные существующие проверки по затронутым компонентам:
  - Изменения в `backend/` -> запустить skill `zamk-backend-check`.
  - Изменения в `apps/seller/` или `packages/api-client/` -> запустить skill `zamk-seller-check`.
  - Изменения в миграциях -> запустить skill `zamk-migration-check`.
  - Подготовка к ручной проверке Product Owner -> запустить skill `zamk-manual-ready`.
- Соблюдать правило остановки: при первом реальном FAIL последующие обязательные проверки не запускаются (NOT RUN).

## 4. Git Diff Check
- Запустить `git diff --check` для контроля отсутствия конфликтов, пробельных ошибок и посторонних символов.

## 5. No Commit / No Push
- Запрещено выполнять `git commit` и `git push`.
- Не добавлять файлы в индекс через `git add .` / `git add -A`.

## 6. Concise Report
- Вернуть краткий технический отчёт: статус проверок, изменённые файлы, подтверждение сохранности стороннего dirty work.
