# Seller Product Flow

## 1. Роли и доступы
- **Seller**: Может создавать свои товары (status `draft`), отправлять на модерацию (`pending_moderation`), обновлять и удалять черновики. Не может видеть чужие товары и не может управлять системными товарами.
- **Admin**: Видит все товары. Может одобрять (`approved`/`published`), отклонять (`rejected` с причиной), блокировать (`blocked`) и скрывать (`hidden`) товары.
- **Customer / Public**: Видит только товары со статусом `published`.

## 2. Статусы товара
- `draft` — черновик, виден только продавцу.
- `pending_moderation` — отправлен на проверку, нельзя редактировать.
- `approved` / `published` — одобрен администратором и виден в публичном каталоге.
- `rejected` — отклонён администратором, продавец видит причину (moderation_comment), может исправить и отправить снова.
- `hidden` — скрыт продавцом или администратором.
- `blocked` — заблокирован платформой за нарушения.
- `out_of_stock` — нет в наличии (может вычисляться автоматически).

## 3. Сценарий продавца (Seller Flow)
1. Продавец заходит в раздел "Товары". Если товаров 0, видит пустой экран с призывом "Добавить первый товар".
2. Нажимает "Добавить товар" и заполняет форму (название, категория, описание, цена, фото, размеры и остатки).
3. Сохраняет как черновик (`draft`) или сразу отправляет на проверку (`pending_moderation`).
4. Остатки (Inventory) инициализируются при создании товара на основе переданных вариантов.
5. Загрузка фото работает через `/api/seller/products/{id}/images/upload`.

## 4. Сценарий модерации (Admin Moderation Flow)
1. Админ заходит в "Товары -> На модерации".
2. Видит список товаров в статусе `pending_moderation`.
3. Может одобрить товар (статус становится `published`) или отклонить с обязательным указанием причины (статус `rejected`).
4. Все действия записываются в лог модерации.

## 5. Публичная видимость (Public Visibility)
- `GET /api/public/products` возвращает только товары со статусом `published`.
- Товары ZAMK (direct-sale) не смешиваются с товарами продавцов на уровне бизнес-логики, но могут выдаваться в общем каталоге.

## 6. Связь с остатками (Inventory Connection)
- При создании вариантов товара (variants) указывается `InitialStock`.
- Бекенд автоматически создаёт запись в `inventory_items` для каждого варианта с указанным `total_stock`.

## 7. Security Rules
- Seller ID берётся строго из токена авторизации.
- Запрещено изменение статуса на `published` продавцом напрямую.
- Rejected reason обязателен при отклонении товара администратором.

## 8. Критерии завершения (UX-2)
- Пустые экраны продавца работают без ошибок (нет 500).
- Продавец может создать товар и отправить на модерацию.
- Админ может одобрить/отклонить товар.
- Товар появляется в магазине только после одобрения.
