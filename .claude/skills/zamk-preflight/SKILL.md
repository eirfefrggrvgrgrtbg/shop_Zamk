# ZAMK Preflight

Цель: до начала работы понять, в каком состоянии рабочее дерево, и не затронет ли задача чужую незакоммиченную работу. Правила Git и контракт FBO — в AGENTS.md и CLAUDE.md, здесь они не повторяются.

Задача пользователя: $ARGUMENTS

Skill только читает. Не выполнять `git add`, `commit`, `push`, `reset`, `clean`, `restore`, `checkout`, `stash` (кроме `list`/`show`), не запускать тесты, сборки, миграции и `finalize.sh`.

## Порядок действий

1. Снять базу одной серией read-only команд (по одной, без `-C` и составных конвейеров): `git branch --show-current`, `git rev-parse HEAD`, `git status --short`, `git diff --cached --name-only`, `git stash list`, `git diff --stat`.
2. Разложить изменённые и неотслеживаемые файлы по областям: аналитика продавца, финансы и возвраты, склад и поставки, Vision, frontend, тесты, конфигурация Claude (`.claude/`, `CLAUDE.md`), прочее. Для каждой области указать число файлов и признак «изменён / новый».
3. Определить файлы задачи. Если `$ARGUMENTS` пусто или не называет файлов, назвать вероятные пути по тексту задачи и явно пометить их как предположение. Не изучать архитектуру заново.
4. Сопоставить файлы задачи с грязными файлами. Для каждого пересечения: файл уже изменён кем-то, значит правки нужно делать поверх существующего diff, читая его, а не перезаписывая файл целиком.
5. Проверить признаки риска:
   - ветка не `main` или detached HEAD;
   - есть проиндексированные файлы (`git diff --cached`) — работа не начата «с нуля»;
   - в `git status` есть конфликтные статусы (`UU`, `AA`, `DD` и т. п.);
   - число stash отличается от ожидаемого (если пользователь назвал ожидаемое число или предыдущую базу);
   - в грязном дереве есть файлы вне ожидаемых областей — «неожиданные», о них сообщить и остановиться по AGENTS.md.
6. Если пользователь назвал защищённые файлы или ожидаемые хеши, сверить их через `shasum -a 256` (только чтение).

## Отчёт

Коротко, на русском:
- Базовая линия: ветка, HEAD (первые 7 символов), число изменённых и неотслеживаемых файлов, число проиндексированных, число stash.
- Области изменений (таблица или список).
- Пересечения с задачей и что из этого следует для правок.
- Что проверено командами и что принято за предположение.
- Вердикт:
  - **READY** — нет пересечений, индекс пуст, ветка `main`, неожиданных файлов нет;
  - **READY WITH OVERLAP** — есть пересечения или чужой diff в файлах задачи; правки только точечные, перед ними прочитать diff файла;
  - **BLOCKED** — конфликты, проиндексированные файлы, неожиданные грязные файлы, detached HEAD или не `main`; ничего не менять, спросить пользователя.

После отчёта остановиться и не начинать задачу.
