# UI продавца (выжимка; источник: `.agents/rules/zamk-seller-ui.md`)

- Сохранять существующий дизайн ZAMK Seller: спокойный, премиальный, не похожий на ERP.
- Минимальные локальные изменения; без массовых рефакторингов и переноса компонентов.
- Типы API должны совпадать с DTO бэкенда; не использовать `any`, не расходиться с контрактом.
- У каждого экрана с данными есть состояния loading, error (с повтором) и empty.
- Добавлять или обновлять подходящие тесты (vitest) для изменённых компонентов.
- Фронтенд не определяет финансовые формулы: суммы, комиссии, return rate и дни покрытия приходят с бэкенда; цены показывать в рублях, не выводить копейки и технические идентификаторы.
- Не хардкодить справочники, которые отдаёт бэкенд; не использовать `alert()` и `confirm()`.
- Визуальную приёмку делает Product Owner, не агент.
